# QHub Split --- Техническое задание v3.3 (MVP)

## Изменения версии 3.3

-   Добавлен полный перечень способов разделения расходов.

    комнаты.

------------------------------------------------------------------------

# 1. Назначение

QHub Split --- сервис совместного учета расходов.

Сервис **не является платежной системой** и не выполняет банковские
переводы.

Он: - ведет совместные расходы; - рассчитывает баланс участников; -
показывает, кто кому сколько должен; - предлагает рекомендуемые
погашения; - позволяет отметить факт погашения задолженности.

------------------------------------------------------------------------

# 2. MVP

## Входит

-   Room Core (только для Split);
-   создание комнаты;
-   приглашение через Messenger, QR и ссылку;
-   совместные расходы;
-   все способы разделения расходов;
-   мультивалютные расходы;
-   расчет баланса;
-   рекомендуемые погашения;
-   отметка погашения долга;
-   экспорт;
-   Offline First.

## Не входит

-   OCR чеков;
-   распределение по позициям чека;
-   AI;
-   карты;
-   повторяющиеся расходы;
-   расширенная аналитика.

------------------------------------------------------------------------

# 3. Архитектура

Room Core создается одновременно со Split и используется только сервисом
Split.

Room Core отвечает за: - комнаты; - участников; - роли; - приглашения; -
QR и ссылки; - события; - синхронизацию.

Split отвечает за: - расходы; - способы разделения; - валюты; -
баланс; - рекомендуемые погашения; - статистику; - экспорт.

------------------------------------------------------------------------

# 4. Расход

Каждый расход содержит:

-   описание;
-   сумму;
-   исходную валюту;
-   курс;
-   категорию;
-   дату;
-   плательщика;
-   участников;
-   способ разделения;
-   комментарий;
-   вложения;
-   геопозицию (необязательно).

------------------------------------------------------------------------

# 5. Способы разделения расходов

Для каждого расхода обязательно выбирается один способ разделения.

## 5.1 Поровну (Equal)

Сумма делится поровну между всеми выбранными участниками.

## 5.2 Фиксированные суммы (Fixed Amount)

Для каждого участника задается конкретная сумма.

Сумма всех долей должна быть равна сумме расхода.

## 5.3 Проценты (Percentage)

Для каждого участника задается процент участия.

Сумма процентов должна быть равна 100%.

## 5.4 Доли (Shares)

Каждому участнику задается количество долей.

Стоимость одной доли рассчитывается автоматически.

## 5.5 Только выбранные участники

Расход распределяется только между отмеченными участниками.

## 5.6 Исключая плательщика

Плательщик оплачивает расход, но сам не участвует в его распределении.

## 5.7 По позициям чека (Receipt Items)

Не входит в MVP.

Будет реализовано после появления OCR.

------------------------------------------------------------------------

# 6. Валюты

Комната имеет одну базовую валюту.

Владелец комнаты вручную задает курсы остальных валют относительно
валюты комнаты.

Все участники используют одинаковые курсы.

Изменение курса влияет **только на новые расходы**.

Каждый расход хранит:

-   amountOriginal;
-   currencyOriginal;
-   exchangeRate;
-   exchangeTimestamp;
-   amountBase.

После создания расхода курс никогда автоматически не изменяется.

Все рекомендуемые погашения отображаются только в валюте комнаты.

------------------------------------------------------------------------

# 7. Расчетный алгоритм

1.  Рассчитать долю каждого участника.
2.  Рассчитать фактически оплаченные суммы.
3.  Вычислить баланс каждого участника.

Баланс = Оплачено − Доля расходов

4.  Определить кредиторов.
5.  Определить должников.
6.  Построить рекомендуемые погашения Greedy-алгоритмом.

------------------------------------------------------------------------

# 8. Greedy-алгоритм

1.  Отсортировать кредиторов по убыванию баланса.
2.  Отсортировать должников по убыванию задолженности.
3.  Максимально погасить долг первого должника перед первым кредитором.
4.  Повторять до закрытия всех балансов.

Алгоритм является приближенным и не гарантирует математически
минимальное число погашений.

------------------------------------------------------------------------

# 9. Округление

Все вычисления выполняются через Decimal.

Для распределения остатка используется Largest Remainder Method.

------------------------------------------------------------------------

# 10. DebtSettlement

Хранит:

-   кто;
-   кому;
-   сумму;
-   валюту комнаты;
-   дату;
-   комментарий.

После первого DebtSettlement связанные расходы блокируются для
изменения. Изменения выполняются только корректирующими расходами.

------------------------------------------------------------------------

# 11. Финансовые принципы

-   Использование float/double запрещено.
-   Используется только Decimal.
-   Источником истины являются Expense и DebtSettlement.
-   Баланс всегда рассчитывается заново.
-   Исторические расходы не пересчитываются после изменения курса.

------------------------------------------------------------------------

# 12. Инварианты

-   Сумма балансов участников всегда равна нулю.
-   Сумма долей всегда равна сумме расхода.
-   После полного погашения баланс каждого участника равен нулю.
-   Любое изменение расходов приводит к перерасчету.
-   DebtSettlement не может превышать текущую задолженность.
-   После появления DebtSettlement связанные расходы блокируются.
-   Архивная комната доступна только для просмотра.
-   Участник с ненулевым балансом не может покинуть комнату.
-   Все рекомендуемые погашения отображаются в валюте комнаты.

# 16. Критерии приемки

MVP считается готовым, если: - работают все способы разделения MVP; -
баланс удовлетворяет всем инвариантам; - рекомендуемые погашения
рассчитываются Greedy-алгоритмом; - офлайн-синхронизация не нарушает
финансовые инварианты; - экспорт работает.

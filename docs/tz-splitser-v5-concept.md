# Splitser v5.0 --- Концепция финансовой модели комнаты

## Цель

Перейти от модели **учёта расходов** к модели **учёта финансовых
операций**.

Комната должна учитывать не только расходы участников, но и любые
движения денежных средств, влияющие на взаиморасчёты и активы комнаты.

------------------------------------------------------------------------

# 1. Основная сущность

Центральной сущностью системы является **Операция (Operation)**.

Все изменения финансового состояния комнаты представляются операциями.

``` text
Operation
 ├── Expense (Расход)
 ├── Contribution (Взнос)
 ├── Settlement (Погашение)
 ├── Transfer (Перевод)
 ├── Withdrawal (Изъятие средств)
 ├── Exchange (Обмен валют)
 ├── Adjustment (Корректировка)
 └── Income (Доход) — опционально
```

Все операции отображаются в единой истории комнаты.

------------------------------------------------------------------------

# 2. Расход (Expense)

Расход представляет собой потребление денежных средств.

**Параметры:**

-   описание;
-   сумма;
-   валюта;
-   категория;
-   источник оплаты;
-   способ распределения;
-   участники распределения.

Источник оплаты не ограничивается участником.

Допустимые источники:

-   участник;
-   общая касса;
-   банковский счёт комнаты;
-   иной актив комнаты.

------------------------------------------------------------------------

# 3. Взнос (Contribution)

Взнос отражает передачу денег или иных активов в распоряжение комнаты.

Пример:

``` text
Борис
↓
Внёс
↓
100 000 KZT
↓
в общую кассу
```

Взнос не является расходом.

Он увеличивает активы комнаты и влияет на итоговый баланс участника.

------------------------------------------------------------------------

# 4. Погашение (Settlement)

Фиксирует факт расчёта между участниками.

Пример:

``` text
Иван
↓
перевёл
↓
20 000 KZT
↓
Борису
```

После операции автоматически пересчитываются взаиморасчёты.

------------------------------------------------------------------------

# 5. Перевод (Transfer)

Перемещение средств между активами комнаты.

Пример:

``` text
Касса
↓
Банковский счёт
```

Не влияет на баланс участников.

------------------------------------------------------------------------

# 6. Изъятие средств (Withdrawal)

Получение участником денег из активов комнаты.

Пример:

``` text
Из общей кассы
↓
Борис
↓
10 000 KZT
```

------------------------------------------------------------------------

# 7. Обмен валют (Exchange)

Фиксирует конвертацию активов.

Пример:

``` text
200 USD
↓
190 EUR
```

Не изменяет взаиморасчёты участников.

Изменяет структуру активов комнаты.

------------------------------------------------------------------------

# 8. Корректировка (Adjustment)

Используется для исправления ошибок и внесения служебных изменений.

Все корректировки должны сохраняться в истории.

------------------------------------------------------------------------

# 9. Активы комнаты

Комната может владеть собственными активами.

Примеры:

-   наличные KZT;
-   наличные USD;
-   банковский счёт;
-   карта;
-   электронный кошелёк.

Пример отображения:

``` text
Активы комнаты

Касса (KZT)   85 000
USD              300
EUR              120
```

------------------------------------------------------------------------

# 10. Источник оплаты

Во всех расходах вместо понятия **«Плательщик»** используется
**«Источник оплаты»**.

Источник оплаты определяет, откуда были списаны средства.

Возможные варианты:

-   Борис;
-   Иван;
-   Общая касса;
-   Банковский счёт комнаты;
-   иной актив.

------------------------------------------------------------------------

# 11. Способ распределения расхода

Способ распределения остаётся свойством расхода.

Поддерживаются:

-   поровну;
-   по долям;
-   по процентам;
-   по суммам;
-   по позициям чека.

После выбора отображается соответствующий интерфейс настройки.

------------------------------------------------------------------------

# 12. Баланс комнаты

Баланс вычисляется не только по расходам.

При расчёте учитываются все операции, влияющие на взаиморасчёты:

-   расходы из личных средств;
-   взносы;
-   погашения;
-   изъятия средств;
-   корректировки.

Баланс отвечает на вопрос:

> Если закрыть комнату сейчас, кто сколько должен получить или
> выплатить?

------------------------------------------------------------------------

# 13. История операций

История комнаты отображает все операции в хронологическом порядке.

Пример:

``` text
09:30  Борис внёс 100 000 KZT в кассу
10:15  Ресторан — 30 000 KZT (оплачено из кассы)
11:20  Такси — 8 000 KZT (оплачено Борисом)
13:10  Обмен 200 USD → 190 EUR
18:40  Иван погасил долг Борису — 15 000 KZT
```

История больше не ограничивается только расходами.

------------------------------------------------------------------------

# 14. Архитектурные принципы

1.  Расход --- это частный случай финансовой операции.
2.  Любое движение денежных средств фиксируется отдельной операцией.
3.  Активы комнаты являются самостоятельной сущностью.
4.  Источник оплаты отделён от потребителя расхода.
5.  История комнаты представляет собой журнал операций (Ledger), а не
    список расходов.
6.  Все взаиморасчёты рассчитываются автоматически на основании полного
    журнала операций.

------------------------------------------------------------------------

## Примечание

Для большинства пользователей интерфейс может оставаться простым:
отображаются только операции **«Расход»** и **«Погашение»**.

Остальные типы операций (**«Взнос»**, **«Обмен валют»**, **«Изъятие»**,
**«Перевод между активами»**) могут быть доступны через режим
**«Расширенный учёт»**, что позволит сохранить простой UX при наличии
мощной архитектурной модели.
